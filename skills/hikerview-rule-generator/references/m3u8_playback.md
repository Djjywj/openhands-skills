# M3U8 / HLS 播放、缓存与加速（官方 help_link / help_js / help_tag 蒸馏）

> 规则给出播放地址后，**缓冲快慢主要取决于「手机 ↔ 视频 CDN」的实际带宽**，规则本身改不了带宽。
> 遇到“加载很慢”，先做**源站测速**判断瓶颈在哪，再决定是否需要缓存 / DNS 优选 / 代理；
> **不要**在没测速的情况下臆测是规则问题。

## 1. HLS 三层结构（排错必看）

```
master playlist  （#EXT-X-STREAM-INF + 变体相对路径，可含 ?sign=...）
   └─ media playlist  （#EXTINF + 分片相对路径；可含 #EXT-X-KEY:AES-128）
         └─ xxx.ts 分片（真正占带宽的部分）
```

- **master 很小（几百字节），分片才大**（几秒一段，常见 100~250KB）。慢是慢在分片下载。
- `#EXT-X-KEY:METHOD=AES-128,URI="key.key"` = 分片加密，播放器要再取 16 字节 `key.key` 解密；
  这是标准 HLS，**多数播放器支持**；若个别播放器不支持，会一直转圈/失败。
- 变体/分片是**相对路径**，由播放器按 base 解析。若播放器解析异常，可让规则**直接返回媒体列表**（见 §5）规避。

## 2. 播放地址的强制识别

| 需求 | 写法 |
|---|---|
| 视频直链 | 末尾加 `#isVideo=true#` |
| 链接里没有 `.m3u8` 字样 | 加 `#m3u8` 或 `#isM3u8#`（后者还会**忽略 content-type 校验**） |
| 不想被当 m3u8 | `#ignoreM3u8#` |

## 3. 索引缓存（针对“地址只能访问一次”）

```js
var a = cacheM3u8('http://xx.m3u8');                    // -> file:///.../video.m3u8##http://xx.m3u8
var b = cacheM3u8('http://xx.m3u8', {headers:{}});      // 支持 headers，用法同 fetch
var c = cacheM3u8('http://xx.m3u8', {}, 'video.m3u8');  // 第 2 参必传（无值给 {}）
var d = batchCacheM3u8([{url:'http://a.cn', options:{headers:{},body:'a=1',method:'POST'}}, {url:'http://b.cn'}]); // 缩写 bcm
```

- **用途**：某些 m3u8 地址只能访问一次，播到一半会断；缓存索引后本地读取，避免二次请求失败。
- 返回串里的 `##原始地址` 用于让播放器把**分片仍按原始地址**解析，别自己拆掉。
- `video://` 链接也可：`{url:'video://https://xxx.html', extra:{cacheM3u8:true}}`。
- 相关：`fixM3u8(url, 内容)` 把 `#EXT-X-KEY`/`xxx.ts` 相对路径补成绝对；
  `clearM3u8Ad(url)` / `clearM3u8AdLazy(url)` 清 `#EXT-X-DISCONTINUITY` 疑似广告段。

## 4. PNG 分段 / 本地代理

- `cacheM3u8WithPngProxy(url, options, fileName)` / `convertM3u8WithPngProxy(content, {headers:{}})`
  用于**分片被伪装成 image/png** 的站：软件起本地代理，把 png 转回 ts。
- `startProxyServer($.toString(()=>{ ... return 内容 }))`：本地代理，**Content-Type 固定 `application/vnd.apple.mpegurl`**。
  - 传给播放器时**必须加唯一参数**（否则地址不唯一会被复用）；
  - 代理代码里用 `MY_PARAMS` 取参数；可返回 `{body, headers, statusCode}` 扩展。
  - 适合：给分片/索引**补请求头**、改写分片地址、做二次处理。

## 5. 慢加载排查套路（本 skill 实战总结）

1. **先测源站**（在规则生成环境/另一网络，用 `curl` 直接拉）：
   - `master`/`media`/`key.key`/前几个 `.ts` 的 `HTTP 码、字节数、耗时、速率`；
   - 连续拉 30+ 次看**是否限速、是否“只能访问一次”**；对比**带/不带 Referer/UA**；换 CDN 的多个 IP 分别测。
2. **区分瓶颈**：源站快 → 瓶颈在“手机↔CDN”或播放器；源站慢/限速 → 才考虑缓存/代理/换线路。
3. **规则侧能做的**（都**不增加带宽**）：
   - 直接返回 **media playlist**（跳过 master 一次往返，且规避相对路径解析问题）；
   - `cacheM3u8` 缓存索引（防“只能访问一次”中断）；
   - `registerDNS({'.域名':'IP1 IP2' | 'https://dns.alidns.com/dns-query'})` 优选节点
     （**首次需用户授权**；配合 `findReachableIP([...])` / `ipping(ip, ms)` 找可用节点）；
   - `startProxyServer` 改写/加头（慎用，代理本身也可能成为开销）。
4. **规则改不了带宽**：若视频只有单档高码率、且手机到该 CDN 只有几十 KB/s，任何写法都救不了——
   如实告知用户（换网络 / 关代理 / 换 DNS / 用缓存下载），不要制造“改规则就能变快”的假象。

### 5.1 决定性对照：手机浏览器 vs App 内播放

**让用户用手机浏览器直接打开播放地址**（media 分表或分片直链）：

| 表现 | 结论 | 规则侧对策 |
|---|---|---|
| 浏览器也慢 | 手机↔CDN 带宽/代理/DNS 问题 | 规则无解；建议关代理、换网络、换 DNS |
| **浏览器秒开、App 内慢** | **App 播放器内核 / 设置问题** | 见下 |

“浏览器快、App 慢”时，规则可试的：
- **直接返回 media 分表地址**（跳过 master，匹配浏览器验证过的形态）：
  `fetch(master)` → 取第一条非 `#` 行 → 相对路径用 `master 目录 + 行` 拼绝对，再 `#isVideo=true#`。
- 给地址加 `#m3u8#` / `#isM3u8#` 强制按 m3u8 识别、忽略 content-type 校验。
- `cacheM3u8` 缓存索引（防止“只能访问一次”导致的反复重取）。
- 让用户检查 App 侧：**播放器内核（EXO/ijk/系统）切换、解码方式（硬/软解）、
  是否开了“自动去广告/缓存 m3u8”、是否有全局代理/VPN、DNS**。
- 让用户长按复制播放地址，用**外部播放器**（MX/VLC）试：外部也快 → 坐实海阔播放器问题。

## 6. 常见站点形态：API 多线路（备用域名）

部分站点前端把 API 域名写成数组并做“**检测到访问速度慢，是否切换到新线路？**”的兜底，例如
`VUE_APP_API_BASE_URL:"https://a.oqd79.com,https://b.v84ik.com"`。
- 取架构时**grep 前端 JS** 找 `VUE_APP_API_BASE_URL` / `apiBaseUrlList` / `getPreUrl` / `v2/getUrl` 这类线索。
- `v2/getUrl` 之类的“完整版”接口常需登录/购买（返回 2002 之类），**不要**当作免费直链用。
- 备用域名只影响**接口**（列表/详情），**不影响视频 CDN**；换线路不等于播放变快。

## 7. 直播流（FLV / HLS）专章：地址"只剩几秒"的两种真因

> 实战来源：虎牙直播海阔源（2026-09-11，用户报「播放几秒自动切到下个清晰度」）。

### 7.1 先分清是哪种断流

| 现象 | 真因 | 修法 |
|---|---|---|
| 点开几秒就断，海阔**自动播列表下一条** | 播放地址**无效/未授权**：直接抄了网页或接口返回的 url，而那份 url 是**网页临时身份**签发的（缺 `u`/`seqid` 之类的字段），CDN 立即断开 | **按官方算法自己重签地址**（见 7.2） |
| 稳定播约 2 分钟后断 | 服务端对**网页通道的长连接**有连接租约（虎牙实测约 2 分钟；官方客户端走原生二进制协议才能到约 7 分钟） | **① 改用 HLS（m3u8）线路**——见 7.5，实测可绕开；② 做不到时只能「自动续播」或接受该长度 |

> ⚠️ **海阔的关键行为**：直播流被服务端断开时，海阔**会把它当作播放结束，自动播列表里的下一条**。
> 因此播放项必须**按画质分组排序**——第一条之后紧跟「同画质的备用线路」，绝不能把低画质排在后面，
> 否则一旦断流自动跳转就直接掉清晰度，用户会以为是程序"自动降画质"（其实是我们自己排的顺序）。

### 7.2 为什么要「重签」而不是「直接抄地址」

很多直播站的播放地址带**时效签名**（`wsSecret` / `wsTime` / `seqid` …）。网页或接口返回的那一份是给**当次网页会话**用的，
你原样重放，短则几秒、长则几分钟就被拒。正解是**移植官方（或成熟开源播放器）的签名算法，在规则里现算**。

### 7.3 移植签名算法的固定套路

1. **先找参照实现，别自己猜。** 优先级：同平台开源播放器（Flutter/Android 客户端）> 油猴脚本 > 抓包比对。
   用户给了脚本/仓库链接时**第一时间去读**——「自动切画质 / 纯净版」这类脚本往往已经解决了你正卡住的问题。
2. 拆清三样：**输入**（从接口返回里取哪些字段）、**常量**（模板、版本号、固定串）、**顺序**（先 md5 还是先拼接）。
3. 用规则内可用能力实现：`md5` / `base64` / `fetch`（见 `references/crypto_sign.md`）；注意 **ES5 约束**（`var`、普通 `for`，
   禁 `let` / `const` / `=>` / 模板字符串）。
4. **64 位运算要手工模拟**：JS 位运算只保证 32 位，64 位循环左移要拆高低 32 位分别算再拼回。
   ```js
   function rotl64(t){ return (t & ~0xffffffff) | ((((t & 0xffffffff) << 8) | ((t & 0xffffffff) >>> 24)) & 0xffffffff); }
   ```
5. **字符串替换语义要对齐**：模板占位符（如 `$0 $1 $2 $3`）若"每种只替换第一次"，JS 的 `String.replace(str, str)` 天然如此；
   写成 `replaceAll` 或带 `g` 的正则就会算错。
6. **构造新 query 时先删旧签名字段再补新的**（`wsSecret`/`seqid`/`u`/`uid`/`uuid`/模板字段…），否则出现重复参数；
   个别字段有**按档位分支**的规则（例如某档必须**删掉** `ratio`），严格照抄参照实现。
7. **保持协议不变**：只改签名，别顺手把 `http` 换成 `https`（或反之）——一次只改一个变量，否则出了结果也归因不了。

### 7.4 验证：两把尺子，缺一不可

- **逻辑正确**：用**另一种语言**（如 Python）独立复算一次签名，与规则 JS 的输出**逐字节比对**。
  `md5` 这类确定性算法可完全离线复算，比对通过即算法无误。
- **端到端可用**：必须真机播一会儿。⚠️ 沙箱/机房 IP 常被目标站判为「冷门/海外节点」，表现为
  HTTP 200 却只下 1MB 左右就 EOF，或 302 到无法 DNS 解析的节点。
  **先用「对照组」排除自己的网络**（拉一个大文件看能否跑满），再下"是对方拒绝"的结论。
- **别让用户反复试错**：把问题设计成**一次就能区分真因**的选择题，例如
  「还是几秒就断 / 播了约 2 分钟才断 / 完全不断了」——三种答案分别对应 7.1 表格的三行。
### 7.5 【实测正解】长连接租约断流 → 改走同一平台的 HLS 线路

> 实战来源：虎牙直播 v5→v6（2026-09-11，用户报「v5 仍会播约 2 分钟就断」）。

**原理**：FLV/HTTP-FLV 是**一条长连接**，连接寿命由 CDN 控制（虎牙网页凭据约 2 分钟，与 `wsTime` 的 24 小时无关）；
HLS 是「取一个 m3u8 → 每 3~5 秒再取一次 m3u8 → 逐个取短分片」，**每次都是独立短请求**，因此不吃长连接的租约。

**做法**（改动极小，值得一试）：
1. 接口返回里**通常同时有 FLV 与 HLS 两套线路**（虎牙：`data.stream.flv.multiLine` 与 `data.stream.hls.multiLine`），
   把首选从 flv 换成 hls 即可，**签名算法完全复用**（同一套 `wsSecret/wsTime/seqid/fm`）。
2. 把 FLV 降级为**最后一条应急播放项**（画质有时更高，但约 2 分钟会断），别删干净。
3. **画质不要想当然**：虎牙的 HLS 也有 `蓝光8M/蓝光4M/超清/流畅` 同一份档位表，但真实码率需实测；
   `EXT-X-STREAM-INF:BANDWIDTH=` 里的值可能只是占位符（实测各档都返回同一个数），别拿它当画质证据。
4. 有的房间签名后的 m3u8 **直接返回媒体列表**（分片），有的返回**主列表**（含 STREAM-INF 再套一层）——
   规则不用管，交给播放器；但**写测试时要兼容这两种情况**。

**必须验的四件事**（缺一不可，`test_v6.py` 是现成模板）：
- 首选项地址里含 `.m3u8`（或 `hls.` 域名）；
- 该地址 HTTP 200 且返回内容含 `#EXTM3U`；
- 列表**不含 `ENDLIST`**，且**隔 20 秒再取一次分片序号会前进**（证明是活直播，不是死快照）；
- 取一个**真实分片**能下载到数据（HTTP 200/206，>1KB）。

**易混淆点**：曾判定「该站 m3u8 列表不更新、只能用 FLV」——那是因为当时用的是**未重签**的地址（实测重签前 403、
重签后 200 且列表是活的）。**先确认地址本身合法，再对线路类型下结论。**

## 8. 直播平台「免登录取流 + 自绘首页」实战（2026-09-11，虎牙 v6 + 斗鱼 v2 → 合并版「斗虎直播」v4）

面向"给我做个 XX 直播的海阔源：免登录、最高画质、能收藏直播间"这类需求，套路已跑通并真机验证。

### 8.1 免登录取流（两家都只用匿名身份）
| 平台 | 取流链路 | 免登录能拿到 |
|---|---|---|
| 虎牙 | `mp.huya.com/cache.php?m=Live&do=profileRoom&roomid=<id>&showSecret=1`（`;get;UTF-8;{referer@https://www.huya.com/}`）→ 若返回 `ui`/`uid` 为空走 `udblgn.huya.com/web/anonymousLogin` 换匿名凭证 → 按官方算法**重签**取 HLS | **蓝光（20M）HLS**，并给同画质 HS/TX/AL 三条线 + 降档 + 应急 FLV |
| 斗鱼 | 先 `passport.douyu.com/lapi/did/api/get?client_id=86` 拿 `did` → `www.douyu.com/wgapi/.../getEncryption?did=` → `www.douyu.com/lapi/live/getH5PlayV1/<rid>` | **原画1080P60 FLV**（多数房间）；登录/粉丝牌档位当前不可用，规则里要**写明**而不是摆个点了没变化的按钮 |

- 要点：**列表页里的房间链接必须带修饰符**（`;get;UTF-8;{referer@平台首页/}`），否则海阔当普通网页用 WebView 打开、纯 JSON 接口弹原文。
- 直播卡片链接再加 `#immersiveTheme#`（沉浸播放），与云帧享等主流规则一致。

### 8.2 自绘首页（收藏 + 分类 + 轮播大图）结构模板
```
headRow()      一句标题（含版本号，方便用户确认装的是哪版）
navRow()       🔥推荐 / 🐯平台A / 🐟平台B / ⭐收藏   ← scroll_button，当前项 backgroundColor 高亮
[收藏开播]     正在直播的收藏 → 最多 6 条 pic_1_full（通栏大图，extra:{gradient:true}）+「看全部」入口
[分类行]       只有一行「常看分类」chips + 末尾「更多分类 ▸」
[列表]         movie_3 / movie_1_left_pic 卡片
[底部]         收藏管理（input:// 添加、select:// 移除）
[🛠 诊断]      PAGE===1 时输出一行纯文本：版本 + 当前各变量值（远程排错神器）
```
- **「按直播间开启置顶轮播」**：收藏只存房间号（本地变量，逗号分隔），进页面/下拉刷新时批量查各房间开播状态，
  开播的排到最上面铺成大图 → 就是用户要的"开播自动进轮播"。
- **分类压到 2/3 级**：把「大区 + 游戏」两级合成**一个** `select://`，标签写成 `网游｜英雄联盟`，
  一次选完直接写两个变量 + `refreshPage(false)`，页面上就少一层菜单。
- **跨大区选游戏**：按游戏 code 在**全部大区**里查它属于哪个大区（否则选娱乐区的游戏会被判"不在当前大区"而弹回第一项）。
- **性能**：一屏要查 N 个房间时用 `batchFetch([{url,options}])`（≤16/批）；先探测 `typeof batchFetch==='function'`，老版本退回逐个 `fetch`。
  实测 8~10 次串行 8~10s → 一次并发 1.5~2s。

### 8.3 验证套路（别只跑一个 PC 桩）
1. `harness.mjs` 拉真实接口跑 4 个页签（首页/平台A/平台B/收藏），看条数与"兜底失败 0"；
2. `selftest.mjs` **模拟点击**每个按钮（分类 chips、收藏增删、大图样式切换），断言变量被正确写入；
3. `harness.mjs ... detail <URL>` 验详情页取流 —— ⚠️ **必须喂「列表里真实产出的那条 URL」**（带 `;get;UTF-8;...` 修饰符），
   喂裸的网页地址（如 `https://www.huya.com/660000`）只会拿到 HTML → 假失败，白排查半天。
