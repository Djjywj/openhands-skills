## 一、链接接管与跳转（最高频）

### 1. 点卡片跳去了原网页 / 详情页空白
- **根因**：顶层 `detail_find_rule` / `searchFind` 的路由上下文丢失或返回为空时，海阔会 fallback 把结果当普通网页打开。
- **修法**：在**每条卡片自己的 `url` 上**追加 `@rule=` 做强接管，与顶层配置解耦：
  ```
  url: 详情地址 + '#immersiveTheme#@rule=js:$.require("引擎名").detail()'
  ```
  `@rule=` 是海阔的**能力强制接管**（【官方】`help_film_list_rules.md`：链接后加 `@rule=列表;标题;图片;描述;链接` 即可用 JS 解析二级），卡片带上它就一定走指定 JS，不会 fallback 成网页。
- **约定**：凡 `js:` 引擎统一产出的卡片（首页/分类/搜索共用同一个 `parseItems`），url 一律追加 `@rule` 接 `detail`；**剧集/播放项用 `play` 接管，不要用 `detail`**（否则点集数会进详情而不是播放）。

### 2. 自绘搜索框点了之后搜不到 / 结果不对
- **根因**：返回了 `hiker://search?s=关键词`。这是海阔**系统级搜索协议**，会丢弃本源、打开 App 自带搜索页，不是你的 `search()`。
- **修法**：`@rule` 接回**本源** search，关键词先写进 myVar：
  ```
  putMyVar('keyword', 输入词);
  return 'hiker://empty#noLoading##noHistory#@rule=js:$.require("引擎名").search()';
  ```

### 3. 报 `Expected URL scheme 'http' or 'https' but was 'error'`
- **根因**：搜索做了"数据层/渲染层分离"（`search()` 只取数、渲染交给 UI 层，末尾不再 `setResult`）后，在**首页上下文里内联执行**了 `search()`。此时 `fetch` 失败返回的字符串 `"error"` 被原生 `ArticleListModel` 当成 URL 去请求。
- **修法**：首页 input 的确认跳转**先开一个专属搜索子页**，再在子页里搜：
  ```
  return $('hiker://empty?page=fypage').rule(function(){ $.require("引擎名").search(); });
  ```
- **配套**：数据层 `fetch` 后必须先判 `htm === 'error'` 再 `HTML` 解析（见 §三.9）。

### 4. 详情页顶部一大块留白
- **修法**：列表/搜索项跳详情的 url 加 `#immersiveTheme#`。**【官方】**`help_js.md`：链接含 `#immersiveTheme#` 页面即沉浸，**只能用于二级和子页面，不支持首页**；请求时会自动清除该标记，不影响详情页内 `fetch(MY_URL)`。
- 【外源实测】补充：海报卡本身写法（title 单行 + desc 多行）只占一半，加 `#immersiveTheme#` 是另一半，两者缺一不可。

### 5. 海报卡/简介行"点了会跳走"
- **修法**：不参与跳转的展示项，`url` 用 `javascript:;`（【官方】`help_link.md` 有 `javascript:` 协议）。信息卡、简介、纯文本行都该用它。

## 二、参数传递

### 6. `getParam('id')` / `getParam('kw')` 总取不到
- **根因**：`hiker://empty?id=x` 这类**占位 URL 的 query 不一定原样保留**，`getParam` 不可靠。
- **修法（在 `js:` 引擎里）**：
  - 详情参数：从 `MY_URL` 自己解析 —— `String(MY_URL).split('#')[0].split('?')[1]`，再正则取 id/type；`getParam` 只做兜底。
  - 搜索词：直接读内置变量 `MY_KEYWORD`，别依赖 `getParam('kw')`。
  - 【官方佐证】`help_rules.md` 里 header 中也能用 `js:` 处理（`Cookie@id.js:input`），但占位页 query 的可靠性官方未承诺。
- **口诀**：`参数信 MY_URL / MY_KEYWORD，别信占位 URL 的 getParam`。

### 7. 分页 URL 被改得面目全非
- **根因**：某些场景下 `url` 字段会被重写（时间戳等）。
- **修法**：用 `MY_PAGE` 自己拼分页参数，拼完先 `log('目标URL=' + u)` 验证。
- **【官方】**`fypage` 不能放 URL 最末尾，末尾要补无效串（如 `?_t=0`）。

## 三、JS 引擎与作用域（最容易整页崩）

### 8. `ReferenceError: "xx" 未定义` —— 序列化回调里引用了闭包变量
- **根因**：`$.toString(cb)` / `$().lazyRule(cb)` / `$().rule(cb)` / `registerTask(cb)` 的**回调体会被序列化后独立求值**，拿不到外层函数的闭包变量（`_H`、`_UA`、`id`、`key`、循环变量……）。
- **【官方】**`help_js.md` 明文警告："远程模块里面不要直接引用非顶层作用域的变量或者函数，比如在箭头函数 `()=>{}` 里面定义变量然后 require 里面直接引用此变量名，应该使用传递参数来引用此变量"。
- **修法**：
  - 能传参就传参：`$.lazyRule(function(u, ua){ ... }, url, ua)`（多参数按序绑定形参）；
  - 或把域名/UA 直接写成**字面量**内联进回调；
  - `registerTask` 用对象参数：`$.toString(function(obj){ var id = obj.id; ... }, {id: id, data: items})`。
- **口诀**：`序列化回调禁闭包，变量走参数传进去`。
- ⚠️ **PC 桩测不出这一类 bug（2026-09-11 真机实测）**：本库的 PC 桩（`test_rule.js` / `harness.mjs` / `selftest.mjs`）里回调是**直接调用**的，
  外层变量还看得见，所以"点了没反应/提示失败"在 PC 上照样全绿。**凡是要写变量、切分类、加收藏的按钮，一律用参数化写法**，
  不要写成 `lazyRule(function(){ ...putVar('dh_nav','hy')... })`。
  可直接抄的写法（海阔官方样例同款）：
  ```js
  $('#noLoading##noHistory#').lazyRule(function(a){
    var p = ('' + a).split('|');
    try{ putVar(p[0], '' + p[1]) }catch(e){}
    try{ putMyVar(p[0], '' + p[1]) }catch(e){}
    refreshPage(false);
    return 'hiker://empty';
  }, '' + vName + '|' + vValue);   // 变量名和值都当实参传进去，只传一个字符串实参
  ```

### 9. `fetch` 返回的字符串 `"error"` 被当成内容解析
- **修法**：拿到抓取结果先过滤：
  ```js
  var htm = fetch(url);
  if (htm && htm !== 'error' && htm.indexOf('<') >= 0) { /* 才去解析 */ }
  ```
- 同理，`JSON.parse(fetch(...))` 要先判空串/`'error'`，否则整页崩。

### 10. 选中态高亮显示成了 `<font color=...>` 原文
- **修法（【外源实测】）**：用全角引号前缀 `‘‘’’`（`\u2018\u2018\u2019\u2019`）包住 HTML，**不要用反引号**：
  ```js
  title: isActive ? '‘‘’’<b><font color="#FF5D50">' + name + '</font></b>' : name
  ```
  【官方】`help_col_type.md` 也确认 `text_1` 支持红/橙混排（用 `““””` / `‘‘’’` 类前缀）。
- 兜底方案：改用 `extra:{backgroundColor:'#FF5D50', textColor:'#FFFFFF'}` 做选中色。

## 四、解析与选择器

### 11. `pdfa` / `pdfh` 取属性命中 0 条
- **症状**：本机语义校验通过，真机 0 条。
- **根因**：目标站把数据放**单引号属性**里（`<li class="x" data-json='{...}'>`），选择器引擎对这类属性不稳。
- **修法**：直接改正则 + `JSON.parse`：
  ```js
  var m = String(html).match(/<li class="dx-vod"[^>]*data-json='([^']+)'/g);
  ```
  先 `replace(/&quot;/g,'"')` 再 `JSON.parse`。
- **判断标准**：`pdfa`/`pdfh` 命中 0 就换正则，别死磕。
- **口诀**：`取属性，正则稳，pdfa 命中零就换手`。

### 11b. 链接取出来是 `/detail/1` 这种相对地址，点进去打不开
- **症状**：PC 桩跑出来链接是 `/detail/1`，真机点卡片跳错/空白。
- **根因**：**`pd` 和 `pdfh` 行为不同**（官方文档明确）：
  - `pd`（=`parseDom`）**会自动补全**域名与 `http://` 前缀；
  - `pdfh`（=`parseDomForHtml`）、`pdfa`（=`parseDomForArray`）**不补全**，原样返回。
  所以 **取 `href`/`src` 这类链接必须用 `pd`**；用 `pdfh` 取就会拿到相对地址。
- **修法**：把取链接的 `pdfh(x,'a&&href')` 改成 `pd(x,'a&&href')`。若真要手动拼绝对地址，海阔**没有** `joinUrl`/`concatUrl` 这类内置函数，得自己写：`url.indexOf('http') === 0 ? url : 'https://站点域名' + url`。
- **判断标准**：桩里输出的「链接」不是 `http(s)://` 开头，就是这个坑。
- 📌 本库 PC 桩已按真实行为对齐（`scripts/test_rule.js` 内自带的 `joinUrl` 辅助函数模拟 `pd` 的补全），所以**桩里能看出这个问题**，别以为是桩的 bug。

### 12. 苹果CMS(stui) 详情页多线路对不上号
- **结构**：线路名在 `<h3 class="title">` 里，每个线路对应后面一个 `<ul class="stui-content__playlist">`。
- **修法**：不要用 `pdfa` 硬绑 class，**按出现顺序把「线路名 h3」与「其后的 ul」配对**（扫描全部 h3 位置 + 全部 ul 位置，为每个 ul 找最近的前置 h3）。
- ⚠️ `sid` 与线路名**无固定映射**，绝不能硬编码"线路 1 = 一号线路"。

### 13. 不要按线路名盲过滤"蓝光 / 超清"
- **坑**：某类型（纪录片、单线路短剧）整个详情只有一条叫"蓝光CO线"的线路，按 `/蓝光|超清/` 过滤会把唯一线路也滤掉 → 剧集全空。
- **判断标准**：该线路**能否 parse 出真实地址**，而不是名字。拿不准就全保留。

### 14. 多线路播放：先分流再解析，别盲目逐条请求
【外源实测】真实源的线路大致三类：
- **直链**：url 本身就是 `.m3u8` / `.mp4` → 直接 `#isVideo=true#`，无需解析；
- **私有编码串**（`AR8A...`、`YYNB-...`、`co_...`）→ 无可用域名，**直接跳过**，别浪费请求；
- **第三方解析线路**（指向别的 `api.php`）→ 需二次请求，且常"已到期"，失败要给明确提示，不要静默失败。

## 五、详情页与播放

### 15. 详情页只甩了一串剧集，没有片子信息
- **规范**：返回顺序固定 `[海报卡] → [剧情简介] → [（可选）小菜单/线路] → [剧集列表]`。
- **坑**：别把长篇简介塞进信息卡的 `desc`（点简介会跳空白页）。信息卡只放短元数据。
- 完整可复制代码见 `detail_layout.md`。

### 16. "展开:"两个字在，点了没反应
- **根因**：`rich_text` 里 `<a>` 的 `href` 用了**双引号**，而 `@lazyRule=.js:` 代码内部全是双引号 → 属性在第一个内层 `"` 处被截断。
- **修法**：`href` **必须用单引号**：`<a href='#noLoading#@lazyRule=.js:...'>展开:</a>`。
- 另：别用 `long_text` 假装折叠（它是整屏阅读样式），也别手写无 `href` 的裸 `<a>展开:</a>`。
- 可复制实现见 `detail_layout.md`。

### 17. 播放地址加了 `@headers=` 反而播不了
- **【外源实测】** 部分 CDN 对额外 header 敏感，播放地址后附 `@headers={...}` 会导致解析/播放异常。
- **修法**：**抓取播放页**时可以带 header（只影响抓取），**返回给播放器的播放地址默认裸奔**；确认防盗链再带。
- **口诀**：`播放地址默认裸，防盗链才带头`。

### 18. 剧集列表列数写死不好看
- **修法**：按集数动态选 `text_2`~`text_5`（如 >30 用 `text_5`，>20 用 `text_4`，>10 用 `text_3`，否则 `text_2`）。

### 19. 多集播放进度互相串
- **【官方】**`help_js.md`（动态更新章节）：**`extra` 中的 `id` 必须全局唯一**，多个页面重复会导致"所有页面都会刷新"，同页重复则只更新第一个。
- **修法**：每集 `extra:{id:'规则名_资源ID_集号'}`。

## 六、状态与持久化

### 20. 重启 App 后登录态/账号就失效
- **规则**：
  - **跨重启持久化** → `setItem` / `getItem` / `clearItem`（网盘 token、账号 cookie 必须用这个）；
  - **会话内临时状态**（当前线路、当前分类、筛选）→ `putVar` / `getVar` / `putMyVar` / `getMyVar`；
  - **需要存对象（JSON）** → 用 `storage0.setItem/getItem` 等（【官方】`help_js.md` 明确：`storage0` 支持存 JSON 对象）。
- **口诀**：`token 用 setItem，别睡 myVar`。

## 七、调试与验证

### 21. 用旧 cookie 调试，反复报需登录 / 444，误判成"该功能要登录"
- **修法**：**先删掉 cookie 文件、只带 UA + Referer 重试一次**再下结论（假阴性）。
- 苹果CMS 的"系统安全验证"（图片验证码）多在**搜索**接口触发且每次必现，规则内无法自动绕过 —— **源能出内容就算可用**，搜索如实提示即可。

### 22. 一定要逐级验证，别一次写完就交付
- 顺序：**首页 → 分类/过滤 → 搜索 → 详情 → 选集 → 播放**，每一级用 `log()` / `setError()` 埋点（打印目标 URL、html 长度、正则命中数、返回条数、首条 JSON）。
- 【官方】`setError()` 会把信息直接显示在页面上，适合真机排障。
- 本机可先用 `scripts/test_rule.js` 跑解析，再上真机。

### 23. 接口签名：先判档再封装
- 【外源实测】分三档：低档（可信 header + 表单）、中档（RSA + AES + MD5 拼盐）、高档（AES-GCM + HMAC 逐行签名 + 设备指纹）。
- **先抓包判断是哪一档**，低档别用高档写法（白写一堆加解密还跑不通）。
- 本库已有的加解密实战见 `crypto_sign.md`。
- **口诀**：`签名先看档，高档未必是王道`。

## 八、外部经验里"不要照抄"的地方（避坑）

采纳 wsh-feiyu/hikerskill 内容时发现的问题，记录在此避免连带抄错：

1. **`list_1` 不是合法 `col_type`**。**权威依据是 App 源码**（`app/src/main/assets/help_col_type.json` 收录 48 个 + `ArticleColTypeEnum.java` 另有 `pic_1_card`/`big_blank_block`），**没有 `list_1`**。该外部技能的空态提示用了 `col_type:'list_1'`（`search-implementation.md` §3），照抄会渲染异常。
   ✅ 空态/提示行请用 **`text_center_1`**、**`text_1`** 或 **`blank_block`**。
   > 📌 本库旧文写"官方 `help_col_type.md` 共 45 个"，**已过时**：在线文档比 App 内置资源少 3 个（`icon_3_fill`/`icon_3_round_fill`/`card_pic_3_center`）。**以 App 为准**，`validate_rule.py` 已按 App 校准。
2. **`setDesc` 不是内置 API**。那是该技能自己定义的一个辅助函数名（`function setDesc(d, desc, num){...}`），不是海阔函数。别在规则里直接调 `setDesc(...)` 而不定义它。
3. **示例代码混用 ES6**（`let`/`const`/箭头函数/模板字符串）。本库默认产出走 ES5 保守约定。
   > 📌 但要分清：这是**约定**不是**技术限制**。实测 2070 条真实规则里，含箭头函数 `=>` 的占 **25%**、`let` **35.8%**、`const` **16.7%**、模板字符串 **5.0%** —— 新版引擎能吃 ES6。
   > 所以：**自家产出统一 ES5**（兼容旧版最稳）；看到他人规则用 ES6，不代表写错了，别去"修"它。详见 `rule_recipes.md`「通用约定」。
4. **口诀里的强调前缀被编码搞坏了**。该库多处写成 `‘‘’’`（U+2018 U+2018 U+2019 U+2019），但正文里出现过 `\u2018\u2018\u2019\u2019` 与"固定为 `‘‘’’`（两个左引号+两个右引号）"两种描述混排，抄之前先按 `col_type.md` 的官方说明确认前缀字符。
5. **该库没有 PC 验证能力**（其 SKILL.md 自述"不内置模拟器，一切以 App 实测为准"）。本库有 `test_rule.js` / `run_rule_js.mjs` / `test_juyue.js`，**规则必须先在本机跑通再谈真机**。

### 24. 「点分类/点按钮」在 url 里塞 JS 后失效 —— 英文分号 `;` 把链接截断了
- **症状**：PC 桩全绿，真机点了按钮只弹原文/没反应；或链接后半截丢失。
- **根因**：海阔 HttpParser 把 **英文分号 `;` 当「请求修饰符」的分隔符**（`url;get;UTF-8;{referer@...}` 就是这个语法）。
  于是 `input://{"js":"var a=1;var b=2"}` 这类**内嵌 JS 里的英文分号会把 url 从分号处截断**。
- **修法**：内嵌 JS 里**不出现英文分号**，语句一律用换行 `\n` 分隔；
  末尾是 `]` / `)` 的行，下一行不要以 `(` / `[` 开头（会被粘成一次调用）。
- **自检**：`grep -n ";" 生成物.json` 里凡是出现在 url 值内的英文分号都要复查。

### 25. 真机导入不了 zip / 「小程序 +」里 zip 是灰的
- **症状**：从本地选 `xxx.hk小程序.zip` 能选中，但点不动 / 提示解析失败。
- **根因**：**部分海阔版本（含 8.83）的导入入口只认「口令/文字/直链」，不认本地 zip**；只有 8.8x 的部分版本或从文件管理器「用海阔打开」才吃 zip。
- **判断**：规则若**只用 `rule.json`**（没有 `require.json` + `libs.zip`）→ 直接导入 **json** 最稳。
  规则若依赖聚阅 / Q模板（`$.require` 之类）→ **必须整包**，只能走 zip；本地点不动就把 zip 放到可访问的直链再导（见 `link_protocols.md` 导入口令）。
- **交付建议（血泪）**：给用户的小程序**同时给「zip」和「rule.json」两份**，并一句话说清"装不上就试另一份"。
  用户已实测过的路线：把包放到自己的服务器出直链 → 手机复制直链 → 海阔自动识别剪贴板导入。

## 九、列表观感：让卡片一样高（封面统一 16:9）
### 26. 首页/列表里图片高矮不一、大图与卡片"格格不入"
- **根因**：不同主播/站点上传的封面比例乱（16:9、1:1、竖屏），`movie_*` / `pic_1_full` 按原比例铺 → 一屏里高矮不齐。
- **修法（2026-09-11 实测有效）**：**在取图时就把封面拉齐成 16:9**，再交给 col_type：
  - 阿里云 OSS 的图（含 CDN 回源）：加 `?x-oss-process=image/resize,m_fill,w_750,h_422`（大图）/ `w_480,h_270`（卡片）。
    实测虎牙 1920×1080 的 133 KB 图 → 480×270 的 24 KB，**又快又齐**。
  - URL 自带 query 的用 `&` 接，例如 `...?spformat=png,webp&x-oss-process=...`。
  - 斗鱼：封面尾部的 `/dy1`（320×180）→ 换成 `/dy4`（1280×720），同样是 16:9 但清晰 4 倍。
  - 通吃写法：`img = img.replace(/\/dy[0-9]\s*$/, '/dy4')`，再按需追加 OSS 裁切参数。
- **验收**：把几个成品 URL 真下载下来用 PIL 看尺寸，比例应一致（16:9≈1.778）。
