# 交付前自检清单

> 交付任何 `rule.json` 之前逐项过一遍。**复杂源（子页面 / 依赖底座 / 多线路 / 带登录）必须走完整个清单。**
> 本清单由开源技能库 wsh-feiyu/hikerskill 的 checklist 改编，并补入本库特有的「PC 验证」与「依赖识别」环节。

## A. 通用

- [ ] 顶层字段齐全：`title` / `author` / `version` / `type` / `group` / `ua` / `url` / 对应 `find_rule`。
- [ ] 替换词正确：`fyclass` 分类、`fypage` 页码、`fyarea`/`fysort`/`fyyear` 筛选；**分页词不放 URL 最末尾**（末尾补 `?_t=0` 之类无效串）。
- [ ] 定义了 `area_name`/`sort_name`/`year_name` 的，`url` 里必须有对应占位符（否则筛选不生效）。
- [ ] 每个选择器 / 正则都是**对着真实 HTML 或真实 JSON 写的**，能说出它命中页面哪一段；没有臆造。
- [ ] `col_type` 合法且与内容匹配（合法清单见 `references/col_type.md`）；**不要写 `list_1` 这类不存在的样式**。
- [ ] `pages` 是**字符串化的 JSON 数组**（不是真数组）。
- [ ] `version` 已按规则递增（改过就 +1）。
- [ ] 规则里没有混入 ES6 语法（`let`/`const`/`=>`/反引号）—— 见 `SKILL.md` 注意事项的语法版本说明。

## B. PC 本机验证（本库特有，先做这步）

- [ ] `python scripts/validate_rule.py <rule.json>` 通过，`[错误]` 为 0。
- [ ] `[依赖识别]` 报告已读：命中依赖 → **交付说明里必须写明需要哪种底座 / 是否连包**。
- [ ] `node scripts/test_rule.js <rule.json> --rule find_rule --url <真实URL> --top 3` 能出条数、标题、海报、链接正确。
- [ ] `--rule searchFind --kw <词>` 搜索解析正常（视频类必测）。
- [ ] `--rule detail_find_rule --url <详情接口>` 能出选集与播放地址。
- [ ] 规则内部自行批量取数的，改用 `scripts/run_rule_js.mjs` 复核条数（`test_rule.js` 会少算）。
- [ ] 聚阅子程序改用 `scripts/test_juyue.js`。

## C. 首页 / 分类 / 搜索

- [ ] 分类名与地址用 `&` 分隔且**数量一一对应**。
- [ ] 搜索占位符 `**` 未被站点自身字符冲突（冲突时换 `%%`）；GBK 站有 `;POST;GBK` 或相应编码处理。
- [ ] 懒加载图片优先取 `data-original` / `data-src`，无封面就留空，不硬凑。
- [ ] 列表项 `url` **带了请求修饰符**（`;get;UTF-8;{referer@站点}` / `;post;…`），否则点进去会被当网页打开、不出选集。
- [ ] 卡片的 `url` 是否追加了 `@rule=js:$.require("引擎").detail()` 强接管（有 js 引擎时推荐）。
- [ ] 跳详情的 url 是否带 `#immersiveTheme#`（防顶部留白）。
- [ ] 自绘搜索框没有用 `hiker://search?s=`，而是 `@rule` 接本源 `search()`。

## D. 详情页

- [ ] 返回顺序为 `[海报卡] + [简介] + [（可选）小菜单/线路] + [选集]`，不是只甩剧集列表。
- [ ] 海报卡 `title` 单行、`desc` 多行元信息（防留白）；海报卡与简介 `url:'javascript:;'`。
- [ ] 简介折叠用 `rich_text` + `<a href='**单引号**...@lazyRule=.js:'>`，能原地展开/收起。
- [ ] 多线路站：`tabs[]` 与 `lists[][]` 索引一一对应；只有 1 条线路时可不输出线路行。
- [ ] 详情只回一套去重剧集（若线路是在播放器内部切换）。
- [ ] 每集 `extra.id` 全局唯一（否则多集进度会串）。

## E. 播放 / 链接分流

- [ ] 视频直链带 `#isVideo=true#`；音频带 `#isMusic=true#`。
- [ ] 播放地址**默认没加** `@headers=`（除非确认防盗链）。
- [ ] 多线路 / 字幕 / 歌词用 `{"urls":[...],"names":[...]}` JSON 字符串，字段名正确。
- [ ] 动态解析用对：点击才解析 → `@lazyRule=`；深层嵌套 → `@rule=` / `.js:`。
- [ ] 序列化回调（`$.lazyRule` / `$.toString` / `registerTask`）内部**没有引用外层闭包变量**（取值一律靠形参传入）。
- [ ] 播放解析失败有兜底提示（`toast://` 或页面提示行），不静默失败。

## F. 特殊站点

- [ ] 登录 / Cookie：取 Cookie 逻辑放在 `preRule` 或引擎入口，登录态用 `setItem/getItem` 跨重启持久化。
- [ ] 有验证码 / 风控（403 / 503 / "Just a moment" / 需等 5 秒）：已处理（Cookie、提示用户或降级）。
- [ ] GBK / GB2312 站已处理编码，不乱码。
- [ ] 图片 / 漫画有防盗链 header；漫画图片相对路径已补全（`//`、`/` 前缀）。
- [ ] 接口签名按档位选择实现（低 / 中 / 高档），没有"用高档写法硬套低档接口"。

## G. 交付

- [ ] 存档到 `<工作区>/海阔视界规则/<title>_rule.json`，并在 `download/` 放一份**英文名副本**。
- [ ] 用 `navigate_to_file` 打开给用户看，并给出**可点击的下载链接**。
- [ ] 说明：规则名、分组 `group`、作者、**当前版本号**、依赖要求、以及 PC 端实测结果。
- [ ] 给出导入步骤（单条规则 / 云口令 / 连包，按第 3 步的架构形态）。
- [ ] 提醒：导入后先清缓存或重启 App；真机复测清单已给到。

## H. 六关真机验证（交付后回收反馈用）

`首页 → 分类/过滤 → 搜索 → 详情 → 选集 → 播放`

任何一关不过 → 先回到对应层用 `log()` / `setError()` 埋点定位，别猜。

> 有任一 `[ ]` 未勾且无正当理由 → 先补齐再交给用户。
