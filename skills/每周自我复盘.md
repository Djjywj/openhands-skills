# 每周自我复盘

本技能让所有对话在开始时自动检查"是否到了每周自我复盘时间"，到点则替我完成一次复盘。目的是让助手沿着"做过的事 → 提炼经验 → 改进技能"这条路持续进步，而不依赖电脑在某个固定时间开机。

## 第一步：每次对话先检查（静默）

在开始处理用户请求之前，运行：

```
python3 ~/.openhands/self-review/selfreview.py due
```

- 输出以 **NOT_DUE** 开头 → 什么都不做，**也不要向用户提起这件事**。
- 输出以 **DUE** 开头 → 进入下面的复盘流程。

## 第二步：复盘流程（三件事）

**先完成用户当前的请求**，再在回复末尾补做复盘；如果用户的请求本身很轻（比如只是一句问候），可以直接先复盘。

1. **采集活动**：运行
   ```
   python3 ~/.openhands/self-review/selfreview.py collect 7
   ```
   阅读输出的活动汇总（含各对话的用户消息与收尾总结）。

2. **提炼与改进**：找出这一周里
   - 做得顺、值得固化的做法；
   - 反复卡壳、值得记下的坑；
   - 如果有明确的、可复用的新经验，就更新 `~/.openhands/skills/` 里对应的技能文件，或追加到 `~/.openhands/self-review/notes.md`。
   - **没有明确收获就不要硬造**；不要删除或大改用户已有的技能，除非很有把握。

3. **写报告并标记完成**：
   - 把报告写到 `~/.openhands/self-review/reports/YYYY-MM-DD.md`（用当天日期），内容包括：本周做了哪些事、学到了什么、给用户的建议。
   - 运行
     ```
     python3 ~/.openhands/self-review/selfreview.py done "一句话总结"
     ```
   - 用中文向用户简短汇报 3~5 行（本周做了什么、学到什么、下次约何时），并告诉用户可以打开报告文件查看。

## 规则

1. 只有 `due` 输出 DUE 时才复盘；NOT_DUE 时绝对不要提起，保持自然对话。
2. 复盘要简洁，不要占用用户太多时间和上下文。
3. 不要因为复盘而打断或拖延用户正在进行的紧急任务。
4. 报告和笔记一律使用简体中文。
5. 除非用户明确要求，不要修改本文件。
